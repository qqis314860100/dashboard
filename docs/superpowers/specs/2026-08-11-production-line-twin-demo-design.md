# 产线数字孪生 Demo 设计

## 目标与范围

为内部技术评审提供一个无需后端的本地可运行演示，证明现有看板可以从静态运营展示演进为数字孪生界面。Demo 必须在一个连续流程中呈现：

1. 模拟遥测数据连续到达并更新产线状态。
2. 产线工站和 AGV 的空间位置、状态与 KPI 同步变化。
3. 一项可控的故障触发告警、生成处置事项，并在确认处置后回写资产状态。

范围限于单条总装产线。它复用当前 Vue 3、TypeScript、Element Plus、ECharts 和既有工业浅色视觉方向；不接入 API、协议网关、真实数据库或三维引擎。

## 体验设计

新增路由 `/digitalDashboard/twin`，名称为“产线孪生演示”。该页面作为独立的评审入口，不改变现有总览和专项看板的数据展示行为。

页面以产线空间地图为唯一主视图。顶部显示同步状态、演示时钟、运行/暂停和“注入故障”控制；周围只保留必要的 OEE、在线设备、产出、WIP、AGV 任务和未处置告警指标。地图上的工站和 AGV 是可点击对象：选择后在右侧检查器显示对象身份、当前状态、最后更新时间、数据质量、关键遥测值与最近事件。

右侧下方显示按时间倒序排列的事件流。故障注入会使“气密检测台 L02”从运行变为告警，更新其压力和节拍，降低总体 OEE，并创建一条高优先级告警及待处理处置项。用户点击“确认处置”后，事项变为已确认，设备恢复运行，事件流追加状态恢复记录。该流程可通过“重置演示”回到初始状态。

动画只表达业务状态：AGV 沿既有二维路线平滑移动，数据刷新时显示短暂同步提示，异常工站和告警项使用既有红/琥珀状态色。不得加入装饰性特效、深色科幻主题或非业务动画。

## 架构与数据流

引入一个仅用于 Demo 的组合式状态模块 `useTwinSimulation`，使模拟逻辑不进入 `dashboardDataSource`，也不影响现有页面。模块持有一个本地资产图和可变 `TwinSnapshot`：

```text
初始资产图 + 演示时钟
        ↓ 每 1 秒
模拟器生成遥测 / AGV 坐标 / 派生 KPI / 事件
        ↓
响应式 TwinSnapshot
        ↓
地图、KPI、资产检查器、事件流、处置项
```

资产模型包含：

- `LineTwin`：产线 ID、名称、基准节拍、OEE、产出、WIP 和同步时间。
- `StationTwin`：现有工位 ID、名称、空间坐标、运行状态、节拍、压力、温度、数据质量和最后更新时间。
- `AgvTwin`：现有 AGV ID、状态、电量、任务、路线进度和二维坐标。
- `TwinEvent`：事件 ID、时间、资产 ID、类型、严重等级、说明和状态变更。
- `TwinAction`：故障关联的处置 ID、负责人、状态和确认时间。

状态计算必须是确定性的。时钟每秒递增一次，AGV 使用每台车的路径进度计算坐标；故障只有在用户点击控制后发生，避免评审时被随机结果干扰。暂停时不更新任何遥测或坐标，重置时销毁当前快照并从种子状态重新创建。

## 组件边界

- `twin/index.vue`：页面组合、路由、控制栏和选中资产状态。
- `useTwinSimulation.ts`：种子数据、定时器、派生 KPI、故障注入、处置确认和重置；负责在组件卸载时停止定时器。
- `TwinLineMap.vue`：渲染工站、生产流和 AGV，发出资产选择事件，不持有业务状态。
- `TwinInspector.vue`：根据选中资产渲染身份、同步元数据和遥测属性。
- `TwinEventStream.vue`：只渲染时间序事件和处置状态，发出处置确认事件。

现有 `LineMap.vue`、`AgvMap.vue` 和 `dashboardDataSource.ts` 保持兼容，除非抽出无行为变化的共享样式或类型确有必要。新公共类型仅添加到 `types.ts`，避免把演示数据伪装成生产接口契约。

## 状态与错误处理

模拟器提供明确的 `running`、`paused`、`faulted` 和 `resolved` 演示状态。缺少选中资产时，检查器展示空状态；找不到资产时不抛出错误并展示“资产不可用”。定时器只能存在一个，重置和卸载时必须清除，防止路由切换后继续更新。

Demo 使用本地数据，不设置网络加载或失败状态。页面须对 1280px 及以上桌面评审屏幕保持完整可用；在较窄桌面宽度时，检查器与事件流可下移，但地图、控制栏和处置操作仍可访问。

## 验收与验证

1. 打开 `/digitalDashboard/twin` 后，能看到模拟器正在运行、AGV 位置变化、同步时间刷新和 KPI 小幅变化。
2. 点击工站或 AGV 后，检查器显示正确对象、遥测数据和最后更新时间。
3. 点击“注入故障”后，L02 状态、相关 KPI、事件流和处置项在同一刷新周期内一致地变化。
4. 点击“确认处置”后，处置状态、事件记录和设备状态一致地恢复；点击“重置演示”恢复种子数据。
5. `npm run typecheck` 与 `npm run build` 通过；以浏览器截图检查主页面与故障态，确认文字不溢出、控件可操作且地图非空。

## 不做的事

- 不接真实 PLC、MQTT、OPC UA、后端 API 或数据库。
- 不实现真实权限、工单派发、历史持久化或告警通知。
- 不构建 3D 场景或预测性模型。
